# Wan3 Prompt Writer Skill 规格

## 需求场景与处理逻辑

将当前已验证的 Wan3 视频 Prompt 写法沉淀为可复用的个人 Skill，供后续创建或改写漫剧视频 Prompt 时自动调用。

Skill 触发场景包括：

- 用户要求写、改、整理、优化 Wan3/万相 3.0 视频 Prompt；
- 用户要求为首帧、首尾帧、全能参考模式编写视频提示词；
- 用户要求在 Prompt 中加入人物、场景、道具参考图或 `@图片`；
- 用户要求把对白、动作、镜头和音效组织成可直接出片的 Prompt；
- 用户指出角色说话时机、动作连续性、参考图绑定或结束状态不清楚。

处理步骤：

1. 判断视频生成模式：`t2v`、`first_frame/I2VA`、`first_last_frame/FL2VA`、`last_frame/L2VA` 或 `reference/Ref2VA`。
2. 读取用户提供的角色、场景、道具和首帧/尾帧信息，建立有序参考图清单。
3. 先确认每张参考图已通过 Wan3 请求真实传递：公网可访问 URL、上传后资源标识，或调用层实际附带的本地图片文件。再按媒体数组顺序建立 `@图片N` 映射，并只在参考图实际承担约束的画面节点插入对应引用，说明锁定的身份、外形、纹理、比例、姿态或空间关系。单独写文件名或文字标签但没有真实图片输入，不算有效 `@图片`。
4. 按画面播放顺序组织动作：承接状态、触发、方向、轨迹、接触/受力、位移、反应、环境变化和收束状态。
5. 将每句对白放在角色完成对应动作、出现口型和发声的位置；不可只在 Prompt 末尾汇总台词。
6. 输出镜头参数，包含景别、视角/机位、焦段（有信息时）、运镜、幅度、速度和手持状态。
7. 输出明确结束状态和声音设计。音效、环境声、配乐可以单独成段，但对白不能只存在于声音总结中。
8. 对首帧模式遵守万相接口限制：不承诺同时上传额外 `reference_image`；需要多张角色/场景/道具图时改用 `reference` 模式。

## 架构与技术方案

创建个人 Skill：

`/Users/zhangzhiyu/.comate/skills/wan3-prompt-writer/SKILL.md`

Skill 本身不调用图片或视频 API，不生成媒体文件，也不修改项目代码。它负责 Prompt 设计和改写规则；具体项目中的 Prompt 文件由调用方根据用户目标写入。

Skill 内部按两种主要输出路线组织：

- 基础/关键帧模式：输出中文或用户指定语言的单镜头 Prompt，核心结构为帧锁定、参考图锚点、单镜头、镜头参数、画面内容、动作内联对白、结束状态、音效。
- 全能参考模式：使用稳定的参考图编号，人物、场景、道具分别作为可追踪对象，在第一次出现和后续实际作用位置继续引用。

## 输出格式

默认中文 Wan3 Prompt：

```text
首帧/首帧与尾帧锁定：锁定开场或开收帧的构图、人物姿态、道具状态和空间关系，全片生效。

生成单镜头。
镜头参数：景别，视角/机位，焦段，运镜，幅度，速度，手持状态。
画面内容：承接前序状态；@图片1（人物图）对应的人物在具体位置执行具体动作；@图片2（场景图）锁定当前空间结构；道具在明确接触点发生运动、受力和状态变化；角色在动作节点说出：「原台词」。
结束状态：人物、道具、空间、情绪和镜头最终停在明确状态，不新增动作、不改变布局。
音效：与动作同步的现场声、环境声和配乐。
```

有对白时，必须采用动作内联或明确的对白时序：

```text
叶生转头看向门口；@图片（叶生.png）对应的叶生在转头过程中声音发虚地说：「你……这是怎么了？」
```

参考图必须与实际上传顺序一致，并在网页中渲染为可点击预览的图片引用：

```text
@图片1（闻笙-正面.png）固定闻笙身份与外形；
@图片2（叶生.png）固定叶生脸部特征；
@图片3（漏风书房.png）固定书房空间结构与光线关系。
```

每个 `@图片N` 必须同时满足：

- Prompt 中存在对应引用；
- Wan3 请求媒体数组的第 N 张图片是真实可读取的图片输入；
- 网页将该引用渲染为可点击元素；
- 点击后可正常打开对应图片预览；
- 网页预览、Prompt 编号、API 上传顺序和文件内容四者一致。

只显示彩色 `@图片N` 文字但无法点击预览，或点击后图片不存在、加载失败、内容与引用不符，都视为无效引用。

## 边界条件与异常处理

- 没有参考图时使用 `t2v` 结构，不伪造 `@图片`。
- 只有首帧时使用首帧/I2VA 结构；只有尾帧时使用尾帧/L2VA 结构；首尾帧都存在时才使用首尾帧/FL2VA 结构。
- 首帧/尾帧模式与额外参考图互斥时，必须明确提示用户选择 `reference` 模式或移除额外参考图。
- 参考图缺少文件名、链接或顺序时，先使用稳定编号并标注待补信息，不把不存在的资源写成已上传资源。
- 台词为空时输出“无台词”，不能编造对白。
- 用户没有提供焦段、视角或手持状态时，不虚构具体摄影参数；只输出已知参数并保留必要的镜头运动描述。
- 动作不能只写“发生战斗”“人物受伤”“镜头推进”等概括，必须补充对象、方向、轨迹、接触点、受力、反应和结束状态。
- 不默认使用逐秒拆分。只有用户明确要求节拍、音画同步或转场时间点时才写时间标记。
- 不把对白重复到 `overall_soundscape` 或纯声音总结中作为唯一对白来源。

## 数据流

```text
用户剧本/分镜/资产信息
  -> Skill 判断模式和参考图角色
  -> 建立 @图片 编号与用途映射
  -> 编排连续动作与对白事件
  -> 生成镜头参数、结束状态和音效
  -> 输出可直接用于 Wan3 的 Prompt
  -> 调用方写入项目 Prompt 文件或提交视频生成接口
```

## 预期结果

- 后续所有 Wan3 Prompt 都遵循同一套可复用格式。
- 人物、场景、道具的参考图出现在它们实际作用的画面动作处。
- 台词位于对应角色动作节点，模型能够理解说话时机。
- 首帧/尾帧与全能参考模式不混用错误参数。
- Prompt 保留连续动作逻辑、镜头参数、结束状态和音效，不依赖空泛概括或末尾台词汇总。
